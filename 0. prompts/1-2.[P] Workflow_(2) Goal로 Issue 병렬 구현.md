### 1) 작업 핵심 목표 및 범위
- `@docs/0.PRD_v1_opus46_fn.md` 및 `@tasks/0.TASKS_LIST_v0_2_opus47_fn.md` 문서를 기반으로, 한 번에 에러 없이 처리 가능한 '최대 단위의 작업 범위'를 산정하여 자율적으로 구현한다.
- 현재 단계에서는 기획서 기반 Phase-0 백엔드 핵심 로직(전체 API Route Handler 및 미들웨어)을 일괄 구현하는 것을 최우선 목표로 한다.
- 백엔드와 프론트엔드를 동시에 작업하여 발생하는 복잡도를 피하기 위해, 로직 검증이 완료된 후 UI 작업을 분리하여 수행한다.

### 2) 작업 세부 규칙
- `@2.[P] Coding Guidelines.md`에 명시된 아키텍처 원칙(Next.js App Router 2계층 구조, Route Handler에서 Prisma 직접 호출 등)을 최우선으로 엄격히 준수한다.
- 작업을 진행하며 기획 문서에 명시되지 않은 모호한 부분이나 의사결정이 필요한 항목을 발견할 경우, 절대 임의로 판단하거나 추측하여 코딩하지 않는다.
- 모호성 발견 즉시 `@tasks/DECISION_CHECKPOINT.md` 문서에 해당 내용을 '핵심' 또는 '부수적' 카테고리로 분류하여 누적 기록한다.
- 태스크 구현 시마다 실시간으로 `task.md` (Task Tracker)의 완료 상태를 갱신하고, 코드를 작성한 후에는 반드시 빌드 검증(`npx tsc --noEmit`)을 수행하여 무결성을 확보한다.

### 3) 종료 조건 및 종료 방법
- **조기 종료 조건 (Halt):** 작업 도중 `DECISION_CHECKPOINT.md`에 누적된 "핵심 의사결정사항(아키텍처 위배, 주요 비즈니스 로직 누락 등)"이 **3가지 이상** 누적되거나, "부수적 의사결정사항(에러 메시지 문구, 단순 UI/UX 속성 누락 등)"이 **10가지 이상** 누적될 경우, 즉시 모든 코드 작성을 중단하고 조기 종료한다.
- **정상 종료 조건:** 설정한 최대 작업 범위(예: Phase-0 API 전체)의 구현 및 타입 검증이 의사결정 임계치를 넘지 않고 100% 완료되었을 때 종료한다.
- **종료 방법:** 조기 종료 또는 정상 종료가 발생하면, 현재까지의 작업 내역과 의사결정 대기 목록을 사용자에게 요약 보고(Walkthrough 생성)하고 다음 지시를 대기한다.

### 4) 기타 제약조건
- 모든 코드는 Next.js 14.2.x 및 TypeScript 최신 문법에 맞게 작성되어야 한다.
- 사전에 합의되지 않은 임의의 외부 패키지 설치나 디자인 패턴 도입은 엄격히 금지한다.
- 터미널에서 전체 DB 스키마를 날리거나 외부 서버에 영향을 줄 수 있는 파괴적인 명령어는 실행 전 반드시 사용자의 명시적인 승인을 요청해야 한다.
